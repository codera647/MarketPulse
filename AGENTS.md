# Project instructions

Use `doc/CHECKPOINT.md` for current implementation evidence and
`doc/MILESTONES.md` for the delivery sequence. The project root is this
repository; preserve existing user changes.

The user has authorized creating the GitHub repository and milestones, and
committing and pushing code when each milestone is completed. At completion:

1. Verify the milestone's acceptance criteria and run relevant tests and lint.
2. Update the checkpoint and milestone evidence; keep unverified gates open.
3. Inspect the staged paths and scan for credentials before committing.
4. Commit and push to the configured remote without asking for the same
   authorization again. Never force-push or overwrite unrelated changes.
5. Close the matching GitHub milestone only after the push succeeds and its
   completion criteria are satisfied. Report the commit and milestone links.

Use the user's GitHub connector when available. If the session lacks GitHub
tools, prepare local work and report the access limitation accurately.

Keep `.env`, `.evn`, credentials, raw provider payloads, databases, datasets,
the virtual environment, and model artifacts out of Git. Do not display
secret values. Trailforge supervises extraction and audit tasks; Agent-Reach
web captures remain supplementary. Keep the agreed six-company scope and
the separate SPY benchmark. No broker order capability is authorized.
